# Agent Guide

This repository is part of the Tether WDK (Wallet Development Kit) ecosystem. It is an Android chat and self-custodial wallet app integrating `wdk-core-kotlin` into Jetpack Compose. Chat and wallet are equally important product pillars, with slightly more priority for chat and ease of use from v0.1 onward. The wallet is a dollar account: only USDC and USDT on Base. Per the user's explicit decision on 2026-10-23, native ETH and Bitcoin were removed from the wallet (assets, balances, sends, receive, signing network, WDK bitcoin module, swap quotes) and the product never mentions ETH gas to the user. The only active flavor is mainnet: Base (8453). USDT is the bridged representation from Ethereum through the Base standard bridge.

## Project Overview
- **Architecture:** MVVM with Jetpack Compose. `WalletViewModel` owns wallet state and WDK calls; independent `ChatViewModel` owns messaging state and serialized IO. Screens observe their `StateFlow`s. Never derive chat keys from wallet seeds.
- **Runtime:** Android (minSdk 33, targetSdk 35, compileSdk 35). The WDK core runs its JavaScript worklet under the hood via the `wdk-core-kotlin` module.

## Tech Stack & Tooling
- **Language:** Kotlin (JVM target 17).
- **UI:** Jetpack Compose with Material 3 (Compose BOM 2024.02.00), light/dark themes and system-following mode (default), with a persisted appearance preference.
- **Localization:** English (default `values/strings.xml`), Spanish (`values-es`) and Portuguese (`values-pt`). Android follows the device language unless the user selects an app language in system settings.
- **Build System:** Gradle (Groovy DSL).
  - Build: `./gradlew assembleMainnetDebug`
  - Install on device/emulator: `./gradlew installMainnetDebug`
  - Mainnet release: `./gradlew assembleMainnetRelease` or `./gradlew bundleMainnetRelease` (requires signing credentials for distributable artifacts).
- **Wallet SDK:** `wdk-core-kotlin`, pinned at revision `79153a0351a796667bc5a7cc2fd3ba55741e7462` in `vendor/wdk-core-kotlin` (see `settings.gradle`).
- **QR Codes:** `com.google.zxing:core`.
- **JDK:** 17 is required.

## Coding Conventions
- **File Naming:** PascalCase for Kotlin files (e.g., `WalletViewModel.kt`, `Screens.kt`).
- **Class Naming:** PascalCase (e.g., `WalletViewModel`, `PendingTx`).
- **Packages:** `org.astianx.midori.one.chat` owns all chat models, state, transport, encryption, media, notifications and UI; `org.astianx.midori.one.wallet` owns wallet models, SDK, persistence, networks and UI. Root contains the app host, navigation, theme, shared UI and localizable text. Chat screens receive navigation callbacks and must not import wallet implementation classes.
- **State:** UI state is modeled as immutable data classes (`WalletUiState`) exposed through `StateFlow`; mutations go through `MutableStateFlow.update`-style copy helpers in the ViewModel.
- **Composables:** Each feature has its own `Screens.kt` and `Components.kt`; app-level screens and shared components remain at the root. Keep feature code in its owning package. `Theme.kt` defines neutral white/charcoal surfaces, a restrained green accent and the type scale. System typography and plain chat backgrounds are the defaults; explicitly saved Manrope/serif, accents and wallpapers remain selectable. Chat groups adjacent bubbles by sender/day/time. Wallet uses flat balance and asset sections, without decorative textures.
- **UI text:** Add every user-facing string to all three catalogs, including errors and accessibility labels. Resolve resources in composables with `stringResource`; keep ViewModel messages as `UiText` so locale changes do not retain old-language strings. Do not display raw SDK/provider exception text. Never translate recovery words, addresses, QR payloads or user-authored messages.
- **Async:** Use `viewModelScope` coroutines for WDK calls; never block the main thread.
- **License:** Project-authored source retains Apache 2.0 (`LICENSE`). The user expressly authorized the GPLv3 Signal OMEMO dependency on 2026-10-06. Preserve its notices and source-distribution obligations; do not describe the combined APK as exclusively Apache. See `THIRD_PARTY_NOTICES.md`.

## Development Workflow
1.  **Build the WDK bundle** (first time only): `./scripts/setup-dev.sh`; Gradle runs `npm ci` with the pinned lockfile and generates the worklet
2.  **Sync:** Open in Android Studio (Hedgehog or newer); Gradle sync picks up the local `wdk-core-kotlin` module.
3.  **Build:** `./gradlew assembleMainnetDebug`
4.  **Run:** `./gradlew installMainnetDebug` on a device/emulator running API 33+.

## Repository Specifics
- **Domain:** Dollar wallet with USDC and USDT on Base only. Sends pay their fee in stablecoin through a paymaster and need no ETH (`docs/envios-sin-eth.md`). Open conflict, not resolved: native P2P orders and the P2P KYC attestation still broadcast ordinary Base transactions that need ETH for gas, and their screens still show that cost; they stay gated/disabled until the user decides whether to drop them or sponsor their gas.
- **Networks:** Base mainnet (`base-rpc.publicnode.com`, chain ID 8453) . WDK aliases are `"base"` and `"base-gasless"` (same EOA, stablecoin sends); the worklet bundle no longer includes the Bitcoin module (the `@tetherto/wdk-wallet-btc` entry is still in the pinned JS lockfile, unused). Contracts, providers and explorers live in `WalletNetwork.kt`. Mainnet replaces the former sandbox per the user's explicit decision on 2026-10-06. No testnet fallback.
- **Key Library:** `WdkCore` from `wdk-core-kotlin` — wallet creation/import (12-word mnemonic), address derivation, balance queries, fee estimation, sending transactions, message signing/verification.
- **Persistence:** Mainnet uses Android Keystore AES-256-GCM to protect both WDK credentials in `wdk_wallet_mainnet`. No plaintext key is saved in preferences. Backups/device transfer are excluded in all variants. The legacy `wdk_wallet` testnet file is retained but never loaded or migrated automatically; create/import a mainnet wallet explicitly. Restore failures must preserve credentials.
- **Explorers:** Broadcast transactions link to `basescan.org`. A hash does not prove confirmation.
- **Testing:** Verify changes by building (`./gradlew assembleMainnetDebug`), running `./gradlew testMainnetDebugUnitTest`, running `python3 scripts/verify-mainnet-networks.py` and `python3 scripts/verify-translations.py`, and running the app on the Pixel 6 API 34 (currently emulator-5554), the primary device required by the user. A temporary second API 33+ emulator is optional for additional coverage. Never clear Pixel 6 app data or replace its wallet for tests. Unit tests use isolated fixtures; visible UI acceptance must use the real local ejabberd and genuine app state, per the user on 2026-10-21. Keep the Pixel 6 emulator window visible. New local lab accounts and test messages are authorized; do not contact unrelated users. Inspect the existing wallet read-only unless a funded transaction is explicitly approved. Resolve the serial by AVD name before installing. Check changed UI in English, Spanish and Portuguese. Keep v0.1 open until both usable chat acceptance and funded wallet acceptance pass; start v0.2 afterward. Pending financial acceptance does not freeze authorized chat work within v0.1.

## Messaging integration
- `SmackMessenger.kt`: Smack 4.5.0, TLS required, legacy OMEMO namespace `eu.siacs.conversations.axolotl`. Encryption is mandatory, with explicit device trust and no plaintext fallback or silently skipped devices.
- `ChatVault.kt` and `EncryptedOmemoStore.kt`: independent Keystore AES-GCM vault for chat credentials, identities, ratchets, trust and history. Read/network failures preserve data. Never use the wallet store for chat.
- Chat vault format 2 uses a random AES-256-GCM data key wrapped by Android Keystore; no plaintext key is persisted. Format 1 is read without modification and migrates only on a successful write. Authentication failures never fall back to old state. Group sends commit ratchet writes together before emitting ciphertext; conflicting state or failed persistence blocks the send.
- The local lab is ejabberd at `localhost:5222`; `5280` is administration, not the message transport. An explicitly configured debug pin permits only the inspected localhost certificate; release has no local trust exception.
- `docs/messaging-integration.md` records the XEP matrix and pending features. Server modules do not prove client support. No claims of universal OMEMO compatibility, audited security or guaranteed background delivery.
- `ChatContacts.kt` and `ChatContactsScreen.kt` use the real roster and confirmed contact proposals. Registration does not use a phone number. Shared links/QRs contain a messaging address (`xmpp:` or validated `midori://contact?address=...`), never a wallet address, secret, phone number or automatic send command. Parsing a link or scanning a QR must only propose a contact; saving requires confirmation. Optional contact aliases and phone numbers are local, account-scoped `ConversationOptions` in the encrypted chat vault, never account discovery or authentication. Android agenda access is optional with `READ_CONTACTS`; read explicit Jabber/XMPP/Midori IM identities only, never infer accounts from numbers/email or upload the address book.
- `SmackProfiles.kt` publishes/loads vCard `FN`, `NICKNAME`, `DESC` and an embedded JPEG/PNG avatar. Preserve unrelated vCard fields; only an explicit item-not-found response permits creating an empty card after a failed read. Never fetch external avatar URLs. Avatars are limited to 64 KiB, own published images are re-encoded to at most 320 pixels without original EXIF, and displayed remote dimensions are checked before decoding. Profile cache is encrypted and account-scoped, capped at 200 entries and 512 KiB of encoded contact-avatar data. Withdrawal removes the managed public fields, not other clients’ vCard fields or copies already received. Protocol/UI implementation does not establish public-server or cross-client acceptance.
- `scripts/test-local-messaging.py --serial emulator-5554` provisions and cleans two temporary local accounts for the opt-in Android test. Never use real contacts or clear app data on a device with a wallet.
- `scripts/test-chat-acceptance.py --avd Pixel_6_API_34 --workspace DIR --report DIR verify reply uncertain background profile emoji document agenda qr registration` is the v0.1 chat acceptance (2026-10-23). It drives the real MainActivity with adb/uiautomator and a separate JVM peer (`LivePeerAgentTest`, file-driven, own encrypted state in `--workspace`). Run `verify` first for a new workspace (it befriends and verifies the peer). `registration` needs `scripts/configure-chat-lab-registration.py enable` (restore with `revert`; the lab also limits registrations to one per ~10 minutes) and signs the phone out of its lab account, so it sets a new password through `ejabberdctl change_password` and signs back in; `document` needs `scripts/forward-local-upload.py` plus `adb reverse tcp:5443 tcp:5443` (the script starts both); `qr` needs the emulator started with `-camera-back virtualscene` and the QR placed as the `wall` poster in `~/Android/Sdk/emulator/resources` (restore `poster.png` and `Toren1BD.posters` afterwards). Start emulators with `-gpu swiftshader_indirect`: with host GL the emulator crashed after `am force-stop` and a crash rolled the app vault back (OMEMO sessions broke). Evidence: `docs/evidence/2026-10-23-v0.1-chat`.
- Chat payload: `midori:content:1` is the only version; `reply` is an additive optional field. `MessageDelivery.UNCERTAIN` = the stanza may have left; retry reuses the ID. The pilot messaging service is configured with `midori.chat.pilotHost/pilotDomain/pilotPort` in `local.properties` (or `MIDORI_CHAT_PILOT_*`); empty keeps the manual form. Registration intent is persisted before the request (`pending-registration` in the vault).
- `scripts/test-live-chat-ui.py --serial SERIAL --avd Pixel_6_API_34 --pin INSPECTED_SHA256 --workspace PRIVATE_DIRECTORY` exercises the real MainActivity and visible emulator with two authorized local ejabberd accounts. Install the debug and androidTest APKs first. It retains the phone account/messages and encrypted peer state for continuity; reuse the same private workspace, never expose its credentials. Wallet navigation is read-only. This is local UI/chat acceptance, not funded acceptance or a full pilot.

- `ChatMedia.kt` encrypts uploads with AES-GCM; `ChatPayload.kt` carries metadata inside OMEMO. Never upload plaintext, auto-download a remote file, follow redirects or expose the full cache through FileProvider. Camera/voice/download previews are private cache copies, cleared on logout.
- `SmackGroups.kt` requires members-only non-anonymous rooms and encrypts to the complete affiliation list, including offline members. Unknown device trust blocks the entire send. Leaving removes autojoin; only an administrator revokes membership.
- Extended local tests: start `python3 scripts/forward-local-upload.py`, then `python3 scripts/test-local-messaging.py --serial emulator-5554 --extended`. The relay binds only loopback and preserves TLS. Tests provision temporary accounts and clean only their own room/uploads.

## Connection and group capacity
- `chat/ChatSession.kt` shares one process session between the host and `ChatConnectionService`. Start the visible foreground service only from a started activity, with a configured account and the background preference enabled. Do not promise delivery under Doze or after force-stop/process termination.
- Retry transient connection failures with bounded backoff; TLS identity and authentication failures need an explicit retry. Never show contacts online after our own connection drops.
- Debug laboratory trust can be configured in ignored `local.properties` using `scripts/configure-chat-lab.py --sha256 INSPECTED_PUBLIC_FINGERPRINT`. The property applies only to localhost on 10.0.2.2/127.0.0.1; release pin is always empty. Never auto-learn a replacement certificate.
- `chat/GroupPolicy.kt` is the source of the current 200-member encrypted-group budget. The 200,000 target is deliberately disabled pending a different group encryption architecture and load acceptance; see `docs/grupos-cifrados-a-escala.md`. Do not truncate recipients or downgrade encryption to claim that capacity.
- Capacity acceptance uses `scripts/test-encrypted-groups.py --serial emulator-5554 --serial emulator-5556 --build-install --report /tmp/groups-200.json`: real JVM peers and one Android sender per emulator with an isolated vault. The inspected localhost server needs the bounded traffic profile in `scripts/configure-group-capacity-lab.py`; the test runner never changes server configuration itself.

## Digital-dollar account and conversion
- Home presents one nominal USDC + bridged-USDT account on Base with an optional breakdown. Missing token balances make the total unavailable, never zero. Use integer units and `BigDecimal`; the nominal sum is not a liquidated USD quote.
- Receive uses the same Base address/QR for both stablecoins. External recipients must specify an accepted asset/network; chat usernames are not verified payment bindings.
- Sends require a short-lived review bound to asset, recipient and amount, then fresh balance/network/fee checks. A larger estimated fee requires another review. `PendingTx` is still process-local; durable history and reconciliation remain pending.
- USDC/USDT sends use the `base-gasless` WDK network (`@tetherto/wdk-wallet-evm-7702-gasless`, same EOA address, Candide bundler/paymaster, EntryPoint v0.8). `GaslessTransfer.kt` owns fee-token choice, the exact-address check against `base`, the amount adjustment when the whole balance is sent, and UserOperation receipt parsing. Its hash is a UserOperation hash: never link it to the explorer until `getUserOperationReceipt` returns the bundle hash. The first send delegates the EOA on-chain (EIP-7702, persistent until revoked). Keep exactly one `bare-node-runtime` in the WDK lock (`overrides` in `scripts/setup-wdk.sh`); nested copies lack linked addons and the `bare-worker/global` patch. Do not enable `isSponsored` without a Candide account and a server-side proxy for its key.
- The former `wallet/swap` quote screen (USDC/USDT to ETH) was removed on 2026-10-23 with ETH/BTC; `scripts/wdk.config.js` has no protocol. `docs/cuenta-dolares-velora.md` is historical; any future USDC/USDT conversion needs a new decision.
- `scripts/verify-velora-routes.py` is read-only. Android live quote tests require the explicit `veloraReadOnly=true` instrumentation argument; Isolated financial instrumentation tests use in-memory wallets; visible UI acceptance uses the existing wallet read-only. Do not use the Pixel 6 wallet for funded acceptance without an explicit transaction decision.
